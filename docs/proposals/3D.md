# 3D 方案选择与点选（未实现）

本文是草案，渲染器还没有三维。不要把 `<Scene3D>`、`rotateX`、`rotateY`、`z`、`perspective` 写进当前的 `.layer`：不认识的标签会被丢掉（`unknown-tag`），不认识的属性会留给 `draw`。

**选定的模型是平面，不是网格。** 一张海报里的每一层仍然是 flex 排出来的二维平面，再放到一个有透视的空间里。点选是这个空间上的纯函数：从画布上的一个像素逆投影到平面，重叠时取得最近的那张。

名字已经在 [SPEC.md 第 14 章](../../SPEC.md) 预留：`rotateX`、`rotateY`、`z`、`perspective`、`Scene3D`。不要挪作他用，也不要另起 `camera`、`rotateZ`、`translateZ`、`z-index`。绕画面法线的旋转继续叫 `rotate`。沿平面法线的位移就叫 `z`，单位是像素。

## 决定

三套成熟写法和本仓库的现状对过之后，采用下面这一条，后面的语法都从它推出来：

1. **场景**用 CSS Transforms Level 2 的 3D rendering context，加上 After Effects 里「3D 图层是一块平面」的限定。`Scene3D` 是这个上下文，不是场景图根节点。
2. **布局**继续用现在的 Yoga。`rotateX`、`rotateY`、`z`、`perspective` 和今天的 `rotate`、`scale` 一样，只影响绘制和点选，不改 `box`。
3. **点选**用 Flutter `RenderTransform.hitTest` 的逆变换：把屏幕点变回元素局部坐标，再判断在不在布局盒子里。同一个上下文里多张平面都命中时，用 Three.js `Raycaster` 的规则，按到相机的距离取最近，而不是只按标签先后。
4. **绘制**留在现有的二维 Canvas 上。子树先画进离屏，再把四边形贴回画布。不换 WebGL，不引进网格。

## 对照了哪几套写法

成熟框架把「元素是什么」「变换改不改布局」「点的是哪一个」分成三件独立的事来写。下表只保留和 Flex Layer 有关的那几条。

| | 元素是什么 | 变换与布局 | 点选怎么写 | 我们借的 | 不借的 |
| --- | --- | --- | --- | --- | --- |
| CSS Transforms 2 | 盒子仍是平面。`transform-style: preserve-3d` 让子元素进入同一个三维上下文；默认 `flat` 先压成一张图 | `transform` 不改布局，百分比解析完才变换 | 用变换后的 border box。实现上把点逆变换回局部坐标。规范没有规定「真的按深度取最前」 | 平面、压平、透视在父级、`z` 正方向朝观众、默认不进三维上下文 | `transform: rotateX()` 这种函数串。本仓库一种效果一个属性 |
| After Effects / Motion | 3D 图层是一块带锚点的平面。合成里开 3D，再加一台相机 | 位置、旋转不回流到排版 | 在合成视图里点平面。选择是编辑器的事，和渲染分开 | 平面 + 一个透视距离就够用。不给每个元素做法线贴图 | 独立相机、灯光、材质、朝向顺序的多种枚举 |
| Three.js | `Object3D` 组成场景图，叶子可以是网格 | 矩阵不参与排版 | `Raycaster.setFromCamera` 之后 `intersectObjects`，结果按 `distance` 排序。`layers` 用来排除不参与点选的对象 | 重叠时按距离排序；点选和绘制分开，点选可以不画出来 | 场景图、网格、灯光、八叉树。那是另一套文件，不是 `.layer` |
| Flutter `Transform` | 子组件先按二维布局，再乘变换 | 明确写了：变换不影响布局约束 | `hitTest` 把指针位置乘逆矩阵，再交给子节点。不可逆时整棵子树点不中 | 逆变换进局部盒子；和现有「`box` 是变换前、`ink` 是变换后」同一条 | `Matrix4` 作为作者要写的属性。作者仍写角度和像素 |

不整个引进其中任何一套。CSS 的压平条件要改写成现有效果名；Three.js 只借排序规则；Flutter 只借逆变换。根号、公式那种「抽一个中性结构再各画各的」不适用于这里：三维没有第二份盒子树，就是在现有 `LayoutNode` 上多三个数和一个上下文。

## 坐标

和现在一样，**y 轴向下**，数字是像素。`Scene3D` 的原点在它盒子的左上角。

`z` 的正方向**朝观众**。观众到 `z = 0` 这张平面的距离就是 `perspective`（像素）。这和 CSS 的 `perspective` 矩阵一致：局部点 `(x, y, z)` 在透视除法之后是

```text
w = 1 - z / perspective
x' = vx + (x - vx) / w
y' = vy + (y - vy) / w
```

`(vx, vy)` 是灭点，默认是 `Scene3D` 盒子的中心。`z` 越大，平面越大。`z` 接近 `perspective` 时会放到无限远；`z >= perspective` 的平面中心在相机上或相机后，不绘制、不参与点选，报 `behind-camera`。

旋转绕 `origin`（已有属性，默认 `center`），单位度。作用在局部点上的顺序，接在今天 `src/matrix.ts` 的 `aroundPivot` 后面：

1. 把 `origin` 平移到局部原点
2. `scale`（仍是一个数，不增加 `scaleX`）
3. `z`
4. `rotateX`，再 `rotateY`，再 `rotate`（绕法线，顺时针为正，和现在相同）
5. 平移回去

先缩放、再绕轴，这样现有只写 `rotate` / `scale` 的文件，矩阵的二维部分和今天一致。`rotateX`、`rotateY`、`z` 都缺省为 0。

`src/matrix.ts` 里的 `Matrix` 是二维仿射，绘制和 `src/report.ts` 的 `nodeMatrix` 都用它。三维用另一套 4×4，只在节点真的写了 `rotateX`、`rotateY`、`z`，或祖先有 `Scene3D` 时启用。没写这些的文件继续走现在的二维路径。

## 布局

Yoga 在元素自己的平面里算，单位仍是像素。`rotateX` 不会把 flex 的 `gap` 变成近大远小；近大远小只出现在投影之后。

报告里的分工保持第 10 章的句子，只把「旋转、缩放」扩成「旋转、缩放和透视」：

- `box`：变换前的布局盒子，只累加平移。
- `ink`：投影之后的轴对齐外接矩形，并和祖先的 `overflow="hidden"` 求过交集。`overflow-canvas` 继续看 `ink`。
- 另加 `quad`：投影后的四个角，画布坐标，顺序为左上、右上、右下、左下。点选和调试用它，不用外接矩形去猜斜着的卡片。

## 上下文和压平

`Scene3D` 建立一个三维上下文。直接放在它里面的、没有被压平的 `Layer` / `use` / 图形，共享这一次透视和这一次深度排序。

普通 `Layer` 的默认行为对应 CSS 的 `flat`：子元素先画进这一层，再作为**一张**平面参与外层的 `Scene3D`。这样现有海报的绘制顺序不变。要让两张卡片互相遮挡、各自带 `z`，就把它们写成 `Scene3D` 的直接子层，而不是再包一层会先合成的 `Layer`。

下面这些已经会把子树合成一张图，合成结果是一张平面，平面里面的 `z` 不能和平面外面的元素交错。合成前，子元素仍可以在这张平面自己的局部里做 `rotateX` / `rotateY`（灭点用外层 `Scene3D` 的，没有外层则见下文的 `flatten-3d`）：

| 已有写法 | 为什么压平 |
| --- | --- |
| `opacity` 小于 1 | 先乘透明度再贴，和 CSS 一样必须先得到一张图 |
| `blur`、`filter`、`grade`、`grade-mask`、`glass`、`backdrop-blur`、`blend`、`noise`、`overlay` | 这些效果的输入就是该节点已绘制像素 |
| `overflow="hidden"` | 裁剪发生在这一层的盒子上，裁完已是二维 |

`Scene3D` 嵌套时，内层先得到一张投影完的图，再作为外层的一张平面。不把两个上下文的平面混在同一次深度排序里。

不在任何 `Scene3D` 里时：

- `rotateX`、`rotateY` 仍绘制。没有灭点，只剩余弦压扁，看起来像被压过的仿射，不是一块立着的卡片。
- `z` 不改变像素。
- 两种都报 `flatten-3d`（`warn`），`hint` 写明包进 `<Scene3D perspective="…">`。

## 绘制

`@napi-rs/canvas` 的 `setTransform` 只有二维仿射，和现在 `paint.ts` 的用法一致。透视除法不能写成一次 `setTransform`。

做法和滤镜同一条路：把这一层（含已压平的子树）画进离屏，得到一张位图，再贴到投影后的四边形上。

四边形不要只切成两个三角形。那样纹理不是透视正确的，卡片上的字会漂。把离屏按网格分成小块，每块用仿射贴；网格密到斜边和字缘不再看出折线即可。块数由四边形在屏幕上的短边决定，写死一个上限，避免一张全屏卡片拆出过多块。

两张平面在空间里相交时**不切分**。按平面中心在视空间里的深度排序，离观众近的后画。深度相同则保持现在的规则：后写的元素画在上面。这一点和浏览器、After Effects 的默认合成一样，要写进规范，避免实现时去做三角形互切。

背面照常绘制。不增加 `backface-visibility`。点选也打得到背面，见下一节。

`z >= perspective`、或投影后 `w <= 0` 的元素跳过绘制。

## 点选

点选不画 PNG。它和 `check` 一样读 `.layer`、做布局、建矩阵，然后回答「这个像素打中谁」。绘制和点选共用同一套 4×4 和同一套压平规则，避免出现「画面上是 A、点中的是 B」。

```ts
pickLayer(source, { x, y }, options?) => {
  hit: { path, id, tag, localX, localY, depth } | null
}
```

`x`、`y` 是根画布上的像素，y 向下。`options` 与 `renderLayer` 共用 `baseDir` 等读文件的字段，不共用 `scale`：点的坐标永远是未缩放的画布像素。

命中区域是**布局盒子**（文字含 padding 和 border，形状是形状的盒子，线条是线宽展开后的盒子），不是字形墨迹。字距中间的空隙也算点中该文字。这和 CSS 的 border box、Figma 点中文本层的方式一致。`ink` 继续只给越界检查和调试用。

算法：

1. 用和绘制相同的矩阵链，找出所有包含该屏幕点的候选。屏幕点先乘祖先的二维矩阵，进入某个 `Scene3D` 之后改成射线：射线从观众位置 `(vx, vy, perspective)` 出发，穿过该点。
2. 把射线乘到元素局部坐标系（父矩阵的逆），与局部平面 `z = 0` 求交。交点的 `(localX, localY)` 落在布局盒子内才算命中。矩阵不可逆时，这棵子树没有命中。
3. 压平过的子树不再用子元素自己的 `z` 和外面的平面比深度。射线先与压平后的那一张平面相交，命中之后在这张平面的二维结果里按绘制顺序取最上面的子元素。
4. 同一个三维上下文里有多个命中时，取 `depth` 最小且为正的一个（离观众最近）。`depth` 是交点到观众的距离，单位像素。距离差小于 0.5px 视为相同，然后取绘制顺序上更靠上的那个。
5. 背面命中有效。不因为法线朝后就丢掉。
6. 相机背后的元素、`opacity` 小于 0.01 的元素、被 `overflow="hidden"` 裁掉的部分，不参与。
7. 都没有命中时 `hit` 为 `null`。这不是错误。

`path` 与报告里的 `path` 相同。`localX`、`localY` 是布局盒子局部坐标，左上角为原点，给 `<draw>` 或后续编辑定位用。

命令行与 `check` 并列，不出图：

```bash
npx tsx src/cli.ts pick examples/card.layer --at 540,700
```

标准输出是一行 JSON：`{ "hit": { "path": "…", "localX": 12, "localY": 8, "depth": 860 } }` 或 `{ "hit": null }`。源文件有 **error** 级问题时退出码为 1，和 `check` 相同。仅仅没有点中，退出码为 0。

调试绘制（`render --debug`）在已有的盒子和着墨框之外，用 `quad` 的四边再描一圈。点选本身不往调试图上打点；要核对某一点时，运行 `pick` 再对照 `path`。

## 在 `.layer` 里怎么写

`perspective` 只写在 `Scene3D` 上。`rotateX`、`rotateY`、`z` 的归属和今天的 `rotate` 相同：`Layer`、`use` 和图形写属性；文字写在 `style` 里。它们作用到整棵子树时，写在外包的 `Layer` 上，不要写在 `<p>` 上。

`Scene3D` 不写 `background`。色块仍用 `Rect`、HTML 的 `background` 或 `<draw>`。它需要 `width` 和 `height`，这样灭点和透视有一个确定的盒子。缺了 `perspective` 时报 `invalid-attr`，`hint` 给出像素值。写在普通 `Layer` 上的 `perspective` 同样是 `invalid-attr`。

```html
<Layer width="1080" height="1920" background="#0f1115">
  <Scene3D width="1080" height="800" cx="540" cy="960" perspective="900">
    <Layer width="640" height="360" cx="540" cy="400" z="80" rotateY="-18" origin="center">
      <img src="cover.png" style="width:640px; height:360px" />
    </Layer>
    <Layer width="640" height="360" cx="540" cy="400" z="-40" rotateY="12">
      <div style="display:flex; flex-direction:column; gap:16px">
        <h1 style="font-size:72px">封面之后</h1>
        <p style="font-size:28px">这一层更远</p>
      </div>
    </Layer>
  </Scene3D>
</Layer>
```

两张卡片是 `Scene3D` 的直接子级，近的那张（`z="80"`）盖住远的。若再包一层带 `opacity` 或 `blur` 的 `Layer`，两张会先合成，再一起倾斜，不能互相穿插。

线条仍然不能放进 flex。要斜着放一组线，包一层 `Layer`，把 `rotateX` 写在这层上。

## 问题码

都挂在现有级别上，不新增级别。

| code | 级别 | 何时 |
| --- | --- | --- |
| `unknown-tag` | warn | 实现之前的 `<Scene3D>`。实现之后这是合法标签 |
| `invalid-attr` | warn | `perspective` 没写在 `Scene3D` 上，或 `Scene3D` 缺 `perspective` / 宽高；`rotateX` 等写在了不允许的位置 |
| `flatten-3d` | warn | `rotateX`、`rotateY`、`z` 出现在所有 `Scene3D` 之外。照常按上一节绘制，`hint` 要求包进 `Scene3D` |
| `behind-camera` | warn | 平面中心的 `z` 大于等于所在上下文的 `perspective`，或投影 `w <= 0`。不绘制、不点选 |
| `overflow-canvas` | error | 语义不变，看投影后的 `ink` |

`grade` 那一类「作用于整棵子树的效果只写在 Layer 上」不改。三维属性不是效果名，不要写进 `grade` 的语法。

## 实现时碰哪里

按这个顺序做。每一步都要让没写三维属性的现有测试保持原样。

1. 4×4 与投影纯函数，以及「只写 `rotate` / `scale` 时与 `aroundPivot` 一致」的测试。不接绘制。
2. `schema` 登记 `rotateX`、`rotateY`、`z`、`perspective`，归属和 `rotate` 对齐；`Scene3D` 进标签表。`flatten-3d`、`behind-camera`、`invalid-attr` 的 `hint` 在这一步就有。
3. 离屏加四边形网格贴图。先做没有 `Scene3D`、只有 `rotateX` 的单层，确认字不漂。
4. `Scene3D` 的透视和按中心深度排序。相交平面不切分，用一张夹具图固定顺序。
5. `pickLayer` 和 `flexlayer pick`。夹具至少包括：单张斜卡片、两张 `z` 不同且屏幕上重叠、压平组内部、相机背后、盒子内但字形外的空隙。
6. 报告补 `quad`。`--debug` 把四边画出来。

## 明确不做

- 网格、灯光、材质、环境贴图、阴影贴图。投影仍用现有的 `shadow`，它在平面局部里，不跟三维光源。
- 独立相机、镜头光圈、景深。透视距离只写在 `Scene3D` 的 `perspective` 上。
- 把相交的两张平面切成碎片再拼接。
- 用墨迹多边形做点选。点选看布局盒子。
- 在 `.layer` 里写矩阵数字或 `matrix3d(...)`。
- 为了三维换成 WebGL。二维海报仍走现在的 Canvas。
